## When to use

- A "More actions ⋯" button on a row or a card
- A menu with submenus, such as File → Export as. For File, Edit and View side by side, use a
  [Menubar](/components/menubar/)
- Settings that toggle or pick one of several, such as a View menu

Not to pick a value for a form — use a Select or a Combobox, which submit with the form.

**Choosing between messages and popups:**

| Component                            | Use it for                                                                                         | For example                                          |
| ------------------------------------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| [Dialog](/components/dialog/)        | Something that needs a decision or input before the user carries on; the page is blocked meanwhile | Confirm a delete, edit a record in a form            |
| [Drawer](/components/drawer/)        | A panel that slides in from an edge and blocks the page; the first choice on a phone               | Share options, a mobile nav, a filter panel          |
| [Popover](/components/popover/)      | Extra content or controls next to a button, while the rest of the page stays usable                | Filter panel, share options, details card            |
| **Menu**                             | A list of actions or settings opened from a button                                                 | "More actions ⋯", a View menu                        |
| [Tooltip](/components/tooltip/)      | A short text label on hover or focus; nothing in it can be clicked                                 | Name of an icon button, a keyboard shortcut          |
| [HoverCard](/components/hover-card/) | A preview of where a link goes, on hover or focus; nothing essential in it                         | A profile behind an @mention, a repository's summary |
| [Toast](/components/toast/)          | A brief confirmation after an action, which goes away by itself                                    | "Saved", "Archived — Undo"                           |
| [Alert](/components/alert/)          | A message that stays in the page until the situation changes                                       | "Your trial ends in 3 days", a form error summary    |

`Menu` opens a list of actions next to the button that opened it. It follows the
[WAI-ARIA menu button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/), and is a
native `popover` anchored like [Popover](/components/popover/): Esc, a click outside and focus
returning to the button are the platform's.

## Anatomy

```tsx
import { Menu } from '@arun-dev/ui';

<Menu.Root>
  <Menu.Trigger />
  <Menu.Popup>
    <Menu.Item />
    <Menu.CheckboxItem>
      <Menu.ItemIndicator />
    </Menu.CheckboxItem>
    <Menu.Group>
      <Menu.GroupLabel />
      <Menu.Item />
    </Menu.Group>
    <Menu.RadioGroup>
      <Menu.GroupLabel />
      <Menu.RadioItem>
        <Menu.ItemIndicator />
      </Menu.RadioItem>
    </Menu.RadioGroup>
    <Menu.SubmenuRoot>
      <Menu.SubmenuTrigger />
      <Menu.Popup />
    </Menu.SubmenuRoot>
  </Menu.Popup>
</Menu.Root>;
```

| Part             | Renders                            | Does                                                       |
| ---------------- | ---------------------------------- | ---------------------------------------------------------- |
| `Root`           | nothing                            | holds `open`, and the setter every other part goes through |
| `Trigger`        | `<button>`                         | opens it; the element it is anchored to, and its label     |
| `Popup`          | `<div>`                            | the list: `popover="auto"`, `role="menu"`                  |
| `Item`           | `<button role="menuitem">`         | one action; activating it closes the menu                  |
| `CheckboxItem`   | `<button role="menuitemcheckbox">` | a setting that is on or off                                |
| `RadioGroup`     | `<div role="group">`               | holds the value of its RadioItems                          |
| `RadioItem`      | `<button role="menuitemradio">`    | one choice in a RadioGroup                                 |
| `ItemIndicator`  | `<span>`                           | the check in a CheckboxItem or RadioItem                   |
| `Group`          | `<div role="group">`               | items under a label                                        |
| `GroupLabel`     | `<div>`                            | names its Group or RadioGroup                              |
| `SubmenuRoot`    | nothing                            | holds a submenu's `open`, as Root does                     |
| `SubmenuTrigger` | `<button role="menuitem">`         | an item of the parent menu that opens the submenu          |

`Trigger` is an unstyled button, so render a [Button](/components/button/) to style it.

## Keyboard

| Key                                 | Does                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------- |
| Enter, Space, ↓ on Trigger          | opens the menu at the first item                                                 |
| ↑ on Trigger                        | opens the menu at the last item                                                  |
| ↓ ↑                                 | the next or previous item, wrapping at the ends                                  |
| Home, End                           | the first or last item                                                           |
| A letter or word                    | the next item whose text starts with what you typed                              |
| Enter, Space on an item             | activates it and closes the menu                                                 |
| Enter, Space on a checkable item    | checks it; the menu stays open                                                   |
| Enter, Space, → on a SubmenuTrigger | opens the submenu at its first item                                              |
| ← in a submenu                      | closes it, focus back on its SubmenuTrigger                                      |
| Esc                                 | closes the menu, focus back on the Trigger; in a submenu, closes only that level |
| Tab                                 | closes every level, and focus moves on past the Trigger                          |

## Items

Put the action in the Item's `onClick`. Activating an item closes the menu; to keep it open —
a toggle, say — call `event.preventComponentHandler()` in your `onClick`.

Disabled items are skipped by the arrow keys. Set `focusableWhenDisabled` on the Root to keep them
in the sequence, so a screen reader announces them as unavailable. They still can't be activated:
the item is `aria-disabled` instead of `disabled`, and your `onClick` isn't called.

## Typeahead

Typing moves focus to the next item whose text starts with what you typed, ignoring case and
accents. Type a letter again to cycle through the items that start with it. Keys typed close
together build one search, so `new f` reaches "New folder": a Space in the middle of a search is
part of it, not a click.

An item's text comes from its `children`. If a component of yours renders the text, typeahead
can't see it, so give the item a `textValue`.

## Checkbox and radio items

<Example name="menu-view-options">
  <MenuViewOptions client:load />
</Example>

A `CheckboxItem` holds its own `checked`, controlled or not. A `RadioGroup` holds one `value`, and
each `RadioItem` inside is checked while that value is its own. Both leave the menu open when
activated, so several settings can be changed in one go; set `closeOnClick` to close it.

Put a `Menu.ItemIndicator` where the check should go. It stays in the layout when unchecked, so
labels line up. The styled one draws a checkmark; pass children to draw your own, such as a dot
for radio items.

`Group` and `RadioGroup` are named by a `GroupLabel` inside them. The arrow keys and typeahead run
through every group as one list, and skip the labels.

## Submenus

<Example name="menu-submenus">
  <MenuSubmenus client:load />
</Example>

Wrap a `SubmenuTrigger` and a `Popup` in a `SubmenuRoot`. The trigger is an item of the parent
menu, so the parent's arrow keys and typeahead reach it, and the submenu opens beside it, on the
right by default. Submenus nest as deep as you need.

- **Keyboard:** Enter, Space or → opens the submenu at its first item, and ← closes it. In a
  right-to-left menu the arrows swap, and you pass `side="left"` to the submenu's `Popup`.
- **Pointer:** resting on the trigger opens the submenu without moving focus. Moving to another
  item of the parent closes it, but not while the pointer is crossing toward the submenu, even
  over other items on the way.
- **Closing:** Esc and a click elsewhere in the parent close one level. Activating an item, or
  Tab, closes every level.

## Notes

- The popup is named by the Trigger through `aria-labelledby`. If you give the Trigger your own
  `id`, name the popup yourself with `aria-label`.
- Restyle every menu with the `--menu-*` tokens, e.g. `--menu-min-width`.
- Types come from the package that owns them:
  `import type { MenuItemProps } from '@arun-dev/headless/menu'`, or
  `ComponentProps<typeof Menu.Item>`.
