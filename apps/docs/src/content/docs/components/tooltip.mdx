## When to use

- The name of an icon-only button
- A keyboard shortcut for a button
- A short hint about a control

Not for anything clickable or long — use a Popover — or essential information that touch users must see.

**Choosing between messages and popups:**

| Component                            | Use it for                                                                                         | For example                                          |
| ------------------------------------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| [Dialog](/components/dialog/)        | Something that needs a decision or input before the user carries on; the page is blocked meanwhile | Confirm a delete, edit a record in a form            |
| [Drawer](/components/drawer/)        | A panel that slides in from an edge and blocks the page; the first choice on a phone               | Share options, a mobile nav, a filter panel          |
| [Popover](/components/popover/)      | Extra content or controls next to a button, while the rest of the page stays usable                | Filter panel, share options, details card            |
| [Menu](/components/menu/)            | A list of actions or settings opened from a button                                                 | "More actions ⋯", a View menu                        |
| **Tooltip**                          | A short text label on hover or focus; nothing in it can be clicked                                 | Name of an icon button, a keyboard shortcut          |
| [HoverCard](/components/hover-card/) | A preview of where a link goes, on hover or focus; nothing essential in it                         | A profile behind an @mention, a repository's summary |
| [Toast](/components/toast/)          | A brief confirmation after an action, which goes away by itself                                    | "Saved", "Archived — Undo"                           |
| [Alert](/components/alert/)          | A message that stays in the page until the situation changes                                       | "Your trial ends in 3 days", a form error summary    |

`Tooltip` shows a short label next to an element while it is hovered or has keyboard focus — a
button's shortcut, or the name of an icon. It is anchored like [Popover](/components/popover/),
by CSS, and describes the element to screen readers whether it is showing or not.

## Anatomy

```tsx
import { Tooltip } from '@arun-dev/ui';

<Tooltip.Root>
  <Tooltip.Trigger />
  <Tooltip.Popup />
</Tooltip.Root>;
```

| Part      | Renders    | Does                                                                      |
| --------- | ---------- | ------------------------------------------------------------------------- |
| `Root`    | nothing    | holds `open` and the hover timers                                         |
| `Trigger` | `<button>` | the element described; carries `aria-describedby` and the anchor          |
| `Popup`   | `<div>`    | the label: `popover="manual"`, `role="tooltip"`, placed by `side`/`align` |

The Trigger is usually an element that already exists — render it through:
`<Tooltip.Trigger render={<Button aria-label="Bold" />}>`. It works on a
`<Popover.Trigger>` too, and the tooltip steps aside when it is pressed.

## When it shows

| Input          | Opens                               | Closes                             |
| -------------- | ----------------------------------- | ---------------------------------- |
| mouse or pen   | after resting for `delay` (600ms)   | `closeDelay` (100ms) after leaving |
| keyboard focus | at once                             | on blur                            |
| touch          | never — there is no hover to end it |                                    |
| a press on it  |                                     | at once                            |
| Esc            |                                     | at once — and only the tooltip     |

Moving straight from one tooltip to the next skips the delay, so reading along a toolbar doesn't
mean waiting on each. The pointer can move onto the tooltip without it closing, so its text can
be read and selected ([WCAG 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus)).

Esc closes the tooltip without closing a [Dialog](/components/dialog/) or Popover underneath it.

## What goes in it

Text only. A tooltip describes the element and is never focused, so a link or button inside it
could not be reached by keyboard. For anything interactive, use a Popover.

<Aside title="Don't put the name here">
Give the Trigger its own accessible name — visible text, or `aria-label` on an icon button. The
tooltip is its _description_: read after the name, and not at all by some screen readers in some
modes. A button named only by its tooltip may be announced as just "button".

</Aside>

Nothing essential should live only in a tooltip either: touch users never see one.

## Events

**Where to attach them.** Each part renders a real element and passes your props on to it, so any
event that element fires — not only those listed here — is a prop on that part. `Tooltip.Root`
renders nothing, so it has only `onOpenChange`.

| Part              | Renders         | Its events, for example                         |
| ----------------- | --------------- | ----------------------------------------------- |
| `Tooltip.Popup`   | `<div popover>` | `onBeforeToggle`, `onToggle`, `onTransitionEnd` |
| `Tooltip.Trigger` | `<button>`      | `onClick`, `onFocus`, `onPointerEnter`          |

`onOpenChange` on the Root reports every open and close, after any delay has run.
`Tooltip.Popup` also takes the popover events, `onBeforeToggle` and `onToggle`, which fire on each
open and close with `event.newState` set to `'open'` or `'closed'`. Stopping an open in
`onBeforeToggle` keeps the tooltip hidden, and `onOpenChange(false)` reports it.

## Placement

`side` picks the side of the trigger, and `align` where along it: flush with its start or
end edge, or centred. With no room on the chosen side, it flips to the opposite one.

## Notes

- Placement works as for Popover: `side` defaults to `top`, it flips when there's no room, and
  an older browser without anchor positioning shows it centred rather than beside the element.
- A disabled `<button>` receives no pointer or focus events, so its tooltip can't show. Explain
  why an action is unavailable in text near it instead.
- Restyle every tooltip with the `--tooltip-*` tokens, e.g. `--tooltip-max-width`.
