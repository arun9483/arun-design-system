## When to use

- A verification code sent by text message or email
- A code from an authenticator app during two-factor sign-in
- A short PIN or a backup code of fixed length

Not for free text or a number of any length — use an Input.

**Choosing between entering text:**

| Component                         | Use it for                                                                  | For example                      |
| --------------------------------- | --------------------------------------------------------------------------- | -------------------------------- |
| [Input](/components/input/)       | One line of text: a name, an email, a search                                | Email address, search box        |
| **OTP input**                     | A code of fixed length, typed or pasted one character per box               | SMS code, two-factor code, PIN   |
| [Textarea](/components/textarea/) | Several lines of free text that may wrap                                    | Comment, description, message    |
| [Combobox](/components/combobox/) | Typing to find and pick from a list of known options                        | Choose a city, add existing tags |
| [Field](/components/field/)       | Not a control: wraps any of these to tie a label, a hint and an error to it | Any form control with validation |

`OtpInput` is one real `<input>` with the boxes drawn over it. The phone's code suggestion
(`autocomplete="one-time-code"`), paste, the numeric keypad and password managers all reach that
one input, so none of them needs special handling.

## Verify a code

<Example name="otp-input-verify" layout="stack">
  <OtpInputVerify client:load />
</Example>

Checking the code is your server's job; the component only collects it. `onComplete` fires
with the code whenever a change leaves every box filled — the last digit typed, a whole code
pasted, or an emptied box filled again — so pass your check to it to verify with nothing more to
press. To test a value yourself, use a pattern such as `/^\d{6}$/`, not `value.length === 6`: a
box emptied in the middle is a space in the value, so `"123 56"` has six characters too.

## Typing and pasting

| Action               | Result                                                                                |
| -------------------- | ------------------------------------------------------------------------------------- |
| Type a character     | Fills the active box and moves to the next. A full code replaces the last box.        |
| Type something else  | Ignored: letters in a numeric code, symbols in an alphanumeric one.                   |
| Paste a whole code   | Replaces the code, with spaces and dashes dropped: "123 456" and "123-456" both work. |
| Paste part of a code | Fills boxes from the caret on, over what they held.                                   |
| Left / Right         | Move one box.                                                                         |
| Delete               | Empties the active box. The boxes after it keep their digits, and the caret stays.    |
| Backspace            | Empties the active box too. On an empty box, moves back and empties the one before.   |
| Press a box          | Moves the caret there, or to the first empty box if the code has not reached it yet.  |

Deleting never shifts the other digits: delete the 4 in `123456` and the boxes read
`1 2 3 _ 5 6`, with the caret still on the empty box, so typing 8 gives `123856`. Until it is
filled the code is incomplete: the value reports the empty box as a space, `"123 56"`, which the
input's `pattern` rejects. An empty box at the end is simply a shorter code, so deleting the
last digit of `123456` gives `"12345"`.

Focus puts the caret on the first empty box, not over the whole code, so the next key never
wipes what is there.

## Where props go

Like [Input](/components/input/), `className` goes on the row of boxes and every other prop goes
on the `<input>`: `id`, `name`, `required`, `autoFocus`, `aria-*` and `ref`. So a
`<label htmlFor>` names the code, and a [Field](/components/field/) works through
`<Field.Control render={<OtpInput />} />`.

## Forms

- **Native forms:** give it a `name` and the code submits with the form. It carries
  `maxLength` and a `pattern` of exactly `length` characters, so with `required` the browser
  stops a short code, and `form.reset()` puts the first value back.
- **react-hook-form:** use `Controller`, passing `field.value` to `value` and
  `field.onChange` to `onValueChange`. The boxes draw the value, so it lives in React, which
  `register()` cannot drive (as with [Radio group](/components/radio-group/)). Pass `field.ref`
  to `ref`, so focus-on-error lands on the input.

```tsx
<Controller
  control={control}
  name="code"
  rules={{ pattern: { value: /^\d{6}$/, message: 'Enter all 6 digits' } }}
  render={({ field, fieldState }) => (
    <OtpInput
      aria-label="Verification code"
      aria-invalid={fieldState.error ? true : undefined}
      ref={field.ref}
      value={field.value}
      onValueChange={field.onChange}
      onBlur={field.onBlur}
    />
  )}
/>
```

## Accessibility

- Screen readers meet one text field with the whole code, not six. The boxes are hidden from
  them.
- Give it a name: a `<label htmlFor>`, a Field, or `aria-label`.
- Set `aria-invalid` to colour every box as an error. A Field does it for you.
