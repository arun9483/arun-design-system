## When to use

- Confirming an action: "Saved", "Message sent"
- Offering a quick Undo after an action
- Background events that need no decision: "Connection restored"

Not for errors that need attention or information that must stay — use an Alert or a Dialog.

**Choosing between messages and popups:**

| Component                       | Use it for                                                                                         | For example                                       |
| ------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| [Dialog](/components/dialog/)   | Something that needs a decision or input before the user carries on; the page is blocked meanwhile | Confirm a delete, edit a record in a form         |
| [Drawer](/components/drawer/)   | A panel that slides in from an edge and blocks the page; the first choice on a phone               | Share options, a mobile nav, a filter panel       |
| [Popover](/components/popover/) | Extra content or controls next to a button, while the rest of the page stays usable                | Filter panel, share options, details card         |
| [Menu](/components/menu/)       | A list of actions or settings opened from a button                                                 | "More actions ⋯", a View menu                     |
| [Tooltip](/components/tooltip/) | A short text label on hover or focus; nothing in it can be clicked                                 | Name of an icon button, a keyboard shortcut       |
| **Toast**                       | A brief confirmation after an action, which goes away by itself                                    | "Saved", "Archived — Undo"                        |
| [Alert](/components/alert/)     | A message that stays in the page until the situation changes                                       | "Your trial ends in 3 days", a form error summary |

A toast is a brief message that stacks at the edge of the window, the bottom right by default,
and closes itself after a few seconds: "Saved", "Archived — Undo".

## Set up once

Put the Provider and one Viewport near your app's root. Then call `useToastManager()` anywhere
below to show a toast:

```tsx
import { Toast, useToastManager } from '@arun-dev/ui';

<Toast.Provider>
  <App />
  <Toast.Viewport />
</Toast.Provider>;

function SaveButton() {
  const toast = useToastManager();
  return <Button onClick={() => toast.add({ title: 'Saved', type: 'success' })}>Save</Button>;
}
```

## What `add` takes

| Option        | Type                 | Does                                                               |
| ------------- | -------------------- | ------------------------------------------------------------------ |
| `title`       | `ReactNode`          | the headline                                                       |
| `description` | `ReactNode`          | the detail, under it                                               |
| `type`        | `string`             | `info`, `success`, `warning` or `error` colour the edge            |
| `timeout`     | `number`             | milliseconds before it closes; `0` keeps it until closed           |
| `priority`    | `'low' \| 'high'`    | `high` is read out at once (`role="alert"`); `low`, when idle      |
| `action`      | `{ label, onClick }` | a button on the toast, such as "Undo". It does not close the toast |
| `onClose`     | `() => void`         | called once, however it closed                                     |
| `position`    | `ToastPosition`      | where this toast shows, instead of the Viewport's `position`       |
| `id`          | `string`             | reuse one to replace a toast                                       |

`add` returns the id. Pass it to `update` to change the text when work finishes, or to `close`.

## Position

Toasts show at the bottom right by default. Set `position` on the Viewport to change it for every
toast, and pass `position` to `add` to send one toast somewhere else:

```tsx
<Toast.Viewport position="top-center" />;

toast.add({ title: 'Link copied', position: 'bottom-left' });
```

The six positions are `top-left`, `top-center`, `top-right`, `bottom-left`, `bottom-center` and
`bottom-right`. Toasts at the top slide down as they arrive, and toasts at the bottom slide up.
A toast with its own position joins a stack at that position, which is still part of the same
toast area, so pausing, Esc and screen-reader announcements work the same.

## Behaviour

- **Timers pause** while the pointer is over the toasts, while focus is in them, and while the
  page is hidden. They resume with the time that was left.
- **Esc** closes the toast that has focus. Focus moves to the toast area, not the page.
- **Screen readers** hear new toasts politely, or at once with `priority: 'high'`.
- **The newest three show** by default (`limit`). The rest wait their turn.
- The toast area sits in the browser's top layer, so toasts draw above everything. While a
  modal [Dialog](/components/dialog/) is open they can be read but not clicked. Everything
  outside a modal dialog is inert. Give toasts that may appear then a `timeout`.

## Your own layout

Pass the Viewport a function of the toasts and lay each out with the parts:

```tsx
<Toast.Viewport>
  {(toasts) =>
    toasts.map((toast) => (
      <Toast.Root key={toast.id} toast={toast}>
        <Toast.Title />
        <Toast.Description />
        <Toast.Close aria-label="Dismiss" />
      </Toast.Root>
    ))
  }
</Toast.Viewport>
```

## Notes

- Keep toasts short, and never the only way to do something. A toast can vanish before
  anyone reaches its Undo, so offer the same action elsewhere.
- For a message that stays on the page, use an [Alert](/components/alert/).
- Restyle with the `--toast-*` tokens.
