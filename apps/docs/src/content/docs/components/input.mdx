## When to use

- Names, email addresses, passwords, numbers
- A search box, with an icon in the slot before the text
- Any single line of free text in a form

Not for text that runs over several lines — use a Textarea — or a choice from known options — use a Select or a Combobox.

**Choosing between entering text:**

| Component                           | Use it for                                                                  | For example                      |
| ----------------------------------- | --------------------------------------------------------------------------- | -------------------------------- |
| **Input**                           | One line of text: a name, an email, a search                                | Email address, search box        |
| [OTP input](/components/otp-input/) | A code of fixed length, typed or pasted one character per box               | SMS code, two-factor code, PIN   |
| [Textarea](/components/textarea/)   | Several lines of free text that may wrap                                    | Comment, description, message    |
| [Combobox](/components/combobox/)   | Typing to find and pick from a list of known options                        | Choose a city, add existing tags |
| [Field](/components/field/)         | Not a control: wraps any of these to tie a label, a hint and an error to it | Any form control with validation |

`Input` is a real `<input>`. Typing, selection, autofill, validation and form submission are all
the platform's, so there is no headless half and nothing to keep in sync. It works with
react-hook-form's `register()` as-is.

## Two elements, one rule

The `<input>` sits inside a `<div class="input">` that draws the border, and the box is always
there, with or without slots. That gives one rule for where props go:

| Prop                                             | Lands on       |
| ------------------------------------------------ | -------------- |
| `className`                                      | the box        |
| `startSlot`, `endSlot`                           | inside the box |
| everything else, including `id`, `ref`, `render` | the `<input>`  |

So a `<label htmlFor>`, `aria-describedby`, `register()` and a focus ref all reach the control,
and `className` is where you set width or margins.

## Slots

`startSlot` and `endSlot` hold anything: an icon, a prefix or unit, a keyboard hint, or a
button. The box sizes itself around them, so wide content like `https://` fits without tuning.

<Aside title="Slot content is yours">
The slot renders what you pass and adds nothing. Mark a decorative icon `aria-hidden`, since the
label already names the field. Give a slot button `type="button"`, its own accessible name and
its own focus style. The box's focus ring follows the text control only, so a focused slot
button draws its own ring and doesn't light up the whole field.

Clicking a decorative icon does not move focus into the input. Moving it would take JavaScript
in `@arun-dev/ui`, which decision 7 rules out. Click targets are the text and the label.

</Aside>

## States

All of them come from the native control, read with `:has()`. There is no `data-*` attribute
to set:

| State    | Set it with                     |
| -------- | ------------------------------- |
| focus    | the platform (`:focus-visible`) |
| invalid  | `aria-invalid` on the input     |
| disabled | `disabled` on the input         |

Point `aria-describedby` at the error text too, so it is read out with the field.

## Notes

- For text-like types only: `text`, `email`, `password`, `search`, `tel`, `url`, `number`.
  Use [Checkbox](/components/checkbox/), [Radio group](/components/radio-group/) or
  [Switch](/components/switch/) for the others.
- Restyle every input with the `--input-*` tokens, e.g. `--input-height` or
  `--input-border-color-focus`.
