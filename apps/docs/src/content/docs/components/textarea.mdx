## When to use

- Comments, messages and descriptions
- Any free text that may run over several lines

Not for a single line — use an Input.

**Choosing between entering text:**

| Component                           | Use it for                                                                  | For example                      |
| ----------------------------------- | --------------------------------------------------------------------------- | -------------------------------- |
| [Input](/components/input/)         | One line of text: a name, an email, a search                                | Email address, search box        |
| [OTP input](/components/otp-input/) | A code of fixed length, typed or pasted one character per box               | SMS code, two-factor code, PIN   |
| **Textarea**                        | Several lines of free text that may wrap                                    | Comment, description, message    |
| [Combobox](/components/combobox/)   | Typing to find and pick from a list of known options                        | Choose a city, add existing tags |
| [Field](/components/field/)         | Not a control: wraps any of these to tie a label, a hint and an error to it | Any form control with validation |

`Textarea` is a real `<textarea>`. Typing, selection, spellcheck, validation and form submission
are all the platform's, so there is no headless half and nothing to keep in sync. It works with
react-hook-form's `register()` as-is.

## One element

Unlike [Input](/components/input/), there is no box and there are no slots. The `<textarea>`
draws its own frame, so every prop lands on it, `className` included. A `<label htmlFor>`,
`aria-describedby`, `register()` and a focus ref all reach the control directly.

## Resizing

The field fills its container's width by default, and the user can drag the corner handle to
change both height and width. Width can shrink to `--textarea-min-width` and grow back to the
container, but never past it, so a dragged field cannot break the layout around it. Set the
starting width with `className` or `style`; the container stays the ceiling.

<Aside title="In a grid, give the column a size">
The ceiling is `max-inline-size: 100%`, which holds in normal flow, in flex layouts and in grid
columns with a definite size. An `auto` grid column instead grows to fit its content, including
a width the user dragged, so the field can push past the grid. Size the column, e.g.
`grid-template-columns: minmax(0, 1fr)`.

</Aside>

To lock a dimension, override `resize` in your own CSS, e.g. `resize: vertical`.

## Auto-resize

`autoResize` makes the field grow with what is typed, from `--textarea-min-height` up to
`--textarea-max-height`, then scroll. Height is no longer the user's to set, so the handle
drags width only.

<Example name="textarea-auto-resize" layout="stack">

<Aside title="CSS only">
Auto-resize is `field-sizing: content`, with no JavaScript measuring the text. Where a browser
lacks it, the textarea keeps its `rows` height and scrolls, just as it would without the prop.

</Aside>

## Controlled

Uncontrolled is the default: pass `defaultValue`, or `register()`, and the value lives on the
`<textarea>`. When something else needs the value as it is typed, such as a counter, a preview or
a reset button, control it with `value` and `onChange`, exactly as with a plain `<textarea>`.
React's `onChange` fires on every keystroke, not on blur.

<Example name="textarea-controlled" layout="stack">
  <TextareaControlled client:load />
</Example>

`autoResize` keeps working, since it sizes to whatever value the element holds. Pass the value as
`value`, not as children.

## States

All of them come from the native control. There is no `data-*` attribute to set:

| State    | Set it with                     |
| -------- | ------------------------------- |
| focus    | the platform (`:focus-visible`) |
| invalid  | `aria-invalid` on the textarea  |
| disabled | `disabled` on the textarea      |

Point `aria-describedby` at the error text too, so it is read out with the field.

## Notes

- Set the starting height with `rows`, and cap input with `maxLength`. Both are native.
- Restyle every textarea with the `--textarea-*` tokens, e.g. `--textarea-min-height` or
  `--textarea-border-color-focus`. They match Input's by default but are independent: changing
  `--input-*` does not move textareas.
