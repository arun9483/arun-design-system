## Controlled

Pass `checked` with `onCheckedChange` and the parent owns the value — the switch will not move
on its own. `onCheckedChange` reports the value being moved to in both modes, so the same
handler works either way.

<Example name="switch-controlled" layout="stack">
  <SwitchControlled client:load />
</Example>

<Aside type="caution" title="Never pass an undefined checked">
The mode is decided once, at mount, and never re-evaluated. A `checked` of `undefined` on the
first render makes the switch **uncontrolled for the rest of its life** — it starts tracking its
own state and ignores every value you pass afterwards. This bites when the value loads
asynchronously. Coalesce at the call site:

```tsx
<Switch.Root checked={x ?? false} onCheckedChange={setX} />
```

`defaultChecked` does not guard against this. It is ignored in controlled mode, and only makes
the first render look correct while the switch has already taken ownership.

</Aside>

## Anatomy

```tsx
import { Switch } from '@arun-dev/ui';

<Switch.Root>
  <Switch.Thumb />
</Switch.Root>;
```

`Switch.Thumb` reads its state from `Switch.Root`, so the two cannot get out of step.

## Behaviour

- Renders a native `<button>`, so focus, `Space` and `Enter` come from the platform rather than
  from JavaScript. Carries `role="switch"` and `aria-checked` per the
  [WAI-ARIA switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/).
- `disabled` uses the platform's own behaviour on a `<button>`. Rendered as anything else the
  attribute would be inert, so the state is synthesised instead — `aria-disabled`, removal from
  the tab order, and neither the toggle nor your own handlers firing.
- `type="button"`, so it never submits an enclosing form by accident.
- Both parts emit `data-checked` / `data-unchecked` / `data-disabled`. Styling reads those
  rather than knowing how the component decides its state:

  ```css
  .switch[data-checked] {
    background: var(--switch-track-bg-checked);
  }
  .switch-thumb[data-checked] {
    transform: translateX(100%);
  }
  ```

- `Switch.Thumb` is `aria-hidden` — the Root already announces the state.
- The thumb transition is disabled under `prefers-reduced-motion`.

## Styling it yourself

The behaviour, keyboard handling and accessibility all come from
[`@arun-dev/headless`](/headless/), which ships no CSS and no class names. `@arun-dev/ui` adds a
stylesheet on top. To bring your own instead, take the same API from the package underneath:

```tsx
import { Switch } from '@arun-dev/headless/switch';
```

Identical props and parts, styled entirely by you.
