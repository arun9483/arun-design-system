`Popover` opens a panel next to the button that opened it. It is a native `popover`, so the
platform supplies the top layer, closing on Esc or a click outside, the Tab order from the trigger
into the panel, and focus returning to the trigger. CSS anchor positioning keeps it attached
through scrolling and resizing — there is no positioning script.

## Anatomy

```tsx
import { Popover } from '@arun-dev/ui';

<Popover.Root>
  <Popover.Trigger />
  <Popover.Popup>
    <Popover.Close />
  </Popover.Popup>
</Popover.Root>;
```

| Part      | Renders    | Does                                                                   |
| --------- | ---------- | ---------------------------------------------------------------------- |
| `Root`    | nothing    | holds `open`, and the setter every other part goes through             |
| `Trigger` | `<button>` | toggles it; the element it is anchored to                              |
| `Popup`   | `<div>`    | the panel: `popover="auto"`, `role="dialog"`, placed by `side`/`align` |
| `Close`   | `<button>` | closes                                                                 |

`Trigger` and `Close` are unstyled buttons, so render a [Button](/components/button/) to style
them. Name the popup with `aria-label`, or `aria-labelledby` pointing at a heading inside it.

## Placement

`side` picks the side of the trigger, and `align` where along it: flush with the trigger's start
or end edge, or centred. When there isn't room, it flips to the opposite side. Try the edges of
the window:

<Example name="popover-sides">
  <PopoverSides client:load />
</Example>

The gap between trigger and panel is `--popover-offset`.

<Aside title="In an older browser">
Placement needs CSS anchor positioning: Chrome 125, Firefox 147 or Safari 26. An older browser
still opens the popover and closes it on Esc or a click outside, but shows it centred in the
window rather than beside the trigger.

</Aside>

## Closing

Every close is a request through `onOpenChange(false)`: `Popover.Close`, Esc, a click outside,
clicking the Trigger again, or opening another popover — only one is open at a time, unless one
is inside the other. Esc and a click outside close the element before anyone is asked, so a
controlled parent that refuses has it reopened.

## Events

`onOpenChange` on the Root reports every open and close, but not what caused it. The popover's
own events on `Popover.Popup` fire on every one too. Yours run before the component's:

| Prop             | Fires                                                                      |
| ---------------- | -------------------------------------------------------------------------- |
| `onBeforeToggle` | before each open and close. `event.preventDefault()` can stop an open only |
| `onToggle`       | after each open and close; `event.newState` is `'open'` or `'closed'`      |

<Example name="popover-events">
  <PopoverEvents client:load />
</Example>

They don't tell Esc from a click outside — both look the same above. If that matters, listen for
the Esc key yourself; a Close button's own `onClick` identifies it.

`onOpenChange(false)` is a request, so it can arrive before the popover is hidden: a Close button
or the Trigger report first, then it hides; Esc and a click outside hide it first. For work that
needs it actually hidden, use `onToggle` with `event.newState === 'closed'`, which always comes
after.

Not reported: opening it by calling `showPopover()` yourself — use `open` and `onOpenChange`
instead — or unmounting it while open.

## Popover or Dialog?

|                 | Popover                       | [Dialog](/components/dialog/) |
| --------------- | ----------------------------- | ----------------------------- |
| page behind it  | stays usable                  | inert                         |
| position        | next to its trigger           | centred                       |
| a click outside | closes it                     | closes it, unless turned off  |
| for             | filters, pickers, small forms | decisions, larger forms       |

## Notes

- The content stays mounted while closed, so it keeps its state between openings.
- `data-side` and `data-align` repeat what you asked for, not where a flip moved it — which side
  it flipped to is not visible to script, so style both sides alike.
- Restyle every popover with the `--popover-*` tokens, e.g. `--popover-max-width`.
- Types come from the package that owns them:
  `import type { PopoverPopupProps } from '@arun-dev/headless/popover'`, or
  `ComponentProps<typeof Popover.Popup>`.
