## When to use

- Choosing a day where the calendar is the content: a delivery slot, an availability view
- Choosing a range of days on the page, such as leave or a stay

When people may also type the date, or space is short, use a
[DatePicker](/components/date-picker/), which opens this calendar from a field.

## Anatomy

```tsx
import { Calendar, RangeCalendar } from '@arun-dev/ui';

<Calendar aria-label="Delivery day" value={date} onValueChange={setDate} />
<RangeCalendar aria-label="Leave" value={range} onValueChange={setRange} maxDays={5} />
```

Each draws Previous and Next buttons, the month, and a grid of days: a table with the weekdays
as column headers and a button per day, named with its full date. Dates are ISO strings,
`YYYY-MM-DD`, in no time zone.

## Picking a range

<Example name="calendar-range">
  <CalendarRange client:load />
</Example>

The first press starts the range and the second ends it, in either order; pressing the same day
twice picks a single day. In between, the range follows the pointer or focus, and
`onValueChange` is called only once it is complete.

`maxDays` limits the range's length, both ends counted. Once the first day is picked, days
further away are disabled. A range can't span a day that can't be picked, so days past the first
unavailable one are disabled too.

## Limits

| Prop                | Does                                                       |
| ------------------- | ---------------------------------------------------------- |
| `min`, `max`        | Days outside are disabled; months past them can't be shown |
| `isDateUnavailable` | A function of the ISO date: `true` disables that day       |
| `maxDays`           | (Range) the longest range, in days, counting both ends     |

A disabled day is drawn struck through and faded. It stays focusable, so the arrow keys keep
moving by the calendar, and a screen reader announces it as unavailable — but it can't be
picked.

## Keyboard

The grid is one Tab stop: the selected day, or today.

| Key                    | Moves focus to                                               |
| ---------------------- | ------------------------------------------------------------ |
| ← / →                  | The previous or next day (swapped in a right-to-left layout) |
| ↑ / ↓                  | The same day of the previous or next week                    |
| Home / End             | The first or last day of the week                            |
| Page Up / Page Down    | The same day of the previous or next month                   |
| Shift + Page Up / Down | The same day of the previous or next year                    |
| Enter / Space          | Picks the focused day                                        |

Moving past the month shows the next one. A day that doesn't exist, such as the 31st of a
shorter month, becomes its last day.

## What each day is: tags, marks and details

<Example name="calendar-hall">
  <CalendarHall client:load />
</Example>

All optional. `getDayInfo` says what a day is; without it the calendar is as above.

```tsx
getDayInfo={(date) => ({
  tags: [isWeekend(date) && 'weekend', 'festival', 'holiday'], // any number; falsy ones dropped
  description: 'Diwali, public holiday',                        // added to the spoken name
  details: <ul>…</ul>,                                          // the card, on hover, focus or tap
})}
```

**Tags** can overlap freely: a festival that is a holiday, on a weekend, with a birthday. Each day
lists them in `data-tags`, so your CSS can style any tag: `[data-tags~='maintenance']`.

**One mark per day.** The day shows a mark for its tag highest in `tagPriority` — by default
booked, holiday, festival, birthday — named in `data-mark`; the rest are for the details card.
Tags outside `tagPriority` style, but mark nothing. Mark the exceptions, not the usual: a dot on
every free day is noise.

| Tag (built in) | Looks                                 | Token                           |
| -------------- | ------------------------------------- | ------------------------------- |
| `weekend`      | a muted number, no mark               | `--calendar-tag-weekend-color`  |
| `holiday`      | a number in the holiday colour, a dot | `--calendar-tag-holiday-color`  |
| `festival`     | a star                                | `--calendar-tag-festival-color` |
| `birthday`     | a diamond                             | `--calendar-tag-birthday-color` |
| `booked`       | struck through                        | `--calendar-tag-booked-color`   |

**Your own colours and shapes** go in `tagStyles`, for built-in tags or your own:
`{ festival: { color: '#db2777', mark: 'star' } }`. Shapes are `dot`, `ring`, `star`,
`diamond`, `bar`, `strike` and `none`. Every mark is a shape as well as a colour, so it does not
rest on colour alone; show a legend beside the calendar, as the example does. On the selected day
the mark takes the day's colour. For anything else per day, `dayProps` adds attributes to its
button.

**The details card** shows a day's `details`: after a short rest of the mouse, at once on keyboard
focus — so the arrow keys show each day's card in turn — and on a tap, which focuses the day. Esc
hides it; inside a DatePicker, a second Esc closes the picker. It describes its day to screen
readers, as a tooltip does, and it is for reading: links or buttons in it can't be reached, since
the arrow keys and Tab belong to the grid. Put actions beside the calendar, acting on the selected
day, as the example's list does.

### Loading from an API

`getDayInfo` is called for every day shown, so it is a lookup in data already loaded. Fetch it
from `onVisibleRangeChange`, called with the first and last day shown when the calendar mounts
and whenever the months shown change — one request per view. While it loads, `loading` marks the
grids busy and holds the marks back. Keep the latest request only, as the example does, or let a
data library such as React Query cache each month; whether days can be picked before the data
arrives is yours, through `isDateUnavailable`.

## Jumping to a month and year

`captionLayout="dropdown"` replaces the month heading with month and year selects, for dates
far from today, such as a date of birth. The years run from `min`'s to `max`'s, or else from 100
years back to 10 ahead. The heading is kept out of sight, still announcing each new month.

```tsx
<Calendar aria-label="Date of birth" captionLayout="dropdown" min="1900-01-01" max={today} />
```

## Locale

Month and weekday names, digits and the first day of the week come from the browser's locale, or
`locale`: `en-US` starts on Sunday, `en-GB` on Monday. `firstDayOfWeek` overrides the week's
start, 0 for Sunday to 6 for Saturday. Translate the names of the Previous and Next buttons and the month and year selects with
`labels`.

## Accessibility

- Each day is a button named with its full date, such as "Friday, October 16, 2026"; today has
  `aria-current="date"`, and the selected days `aria-selected`.
- The month heading is a live region, so a screen reader announces the new month as it changes.
- Each grid is named by its month. Give the calendar an `aria-label` saying what is picked.
- Selection is drawn as a filled day, and a range as a band between filled ends; today is bold
  and in the accent colour.
