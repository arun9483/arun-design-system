## When to use

- Picking from a long list by typing: cities, people, products
- Choosing several values, shown as chips: reviewers, labels
- Options searched or loaded from a server as people type or scroll

Not for a short list people can scan — use a Select or a RadioGroup.

**Choosing between choosing one option or a value:**

| Component                              | Use it for                                                                          | For example                               |
| -------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------- |
| [RadioGroup](/components/radio-group/) | Up to about five options, all visible at once, as a form value                      | Shipping speed, plan size                 |
| [Select](/components/select/)          | One option from a longer list, in little space, with the system picker              | Country, time zone, sort order in a form  |
| **Combobox**                           | A long list people search by typing, several picks, or options loaded from a server | Assign reviewers, search a city, add tags |
| [ToggleGroup](/components/toggle/)     | A few options shown as buttons that apply at once, not a form field                 | Text alignment, list or grid view         |
| [Slider](/components/slider/)          | A number in a range, where dragging is easier than typing an exact value            | Volume, brightness, price range           |

**Choosing between entering text:**

| Component                           | Use it for                                                                  | For example                      |
| ----------------------------------- | --------------------------------------------------------------------------- | -------------------------------- |
| [Input](/components/input/)         | One line of text: a name, an email, a search                                | Email address, search box        |
| [OTP input](/components/otp-input/) | A code of fixed length, typed or pasted one character per box               | SMS code, two-factor code, PIN   |
| [Textarea](/components/textarea/)   | Several lines of free text that may wrap                                    | Comment, description, message    |
| **Combobox**                        | Typing to find and pick from a list of known options                        | Choose a city, add existing tags |
| [Field](/components/field/)         | Not a control: wraps any of these to tie a label, a hint and an error to it | Any form control with validation |

`Combobox` is a text input that filters a list as you type. It follows the
[WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), and behaves as
[Base UI's Combobox](https://base-ui.com/react/components/combobox) does. The list is a native
`popover`, anchored to the field with CSS like [Popover](/components/popover/).

Use [Select](/components/select/) for a short list nobody needs to search.

## Anatomy

```tsx
import { Combobox } from '@arun-dev/ui';

<Combobox.Root items={items}>
  <Combobox.Input />
  <Combobox.Popup>
    <Combobox.Status />
    <Combobox.Empty />
    <Combobox.List>{(item) => <Combobox.Item key={item} value={item} />}</Combobox.List>
  </Combobox.Popup>
</Combobox.Root>;
```

| Part         | Renders                     | Does                                                                             |
| ------------ | --------------------------- | -------------------------------------------------------------------------------- |
| `Root`       | hidden inputs, with `name`  | holds the items, the selection, the text and `open`; filters the items           |
| `Input`      | `<div>` around an `<input>` | the field: chips, the text, Clear and a chevron, and what the list lines up with |
| `Popup`      | `<div>`                     | the box the list opens in: `popover="manual"`, as wide as the field              |
| `List`       | `<div role="listbox">`      | renders its function once per item the filter left                               |
| `Item`       | `<div role="option">`       | one option, with a check while selected                                          |
| `Group`      | `<div role="group">`        | items under a label, as an `<optgroup>`; optional                                |
| `GroupLabel` | `<div>`                     | the group's name, shown but not an option                                        |
| `Separator`  | `<div aria-hidden>`         | a line between items or groups, as an `<hr>` in a `<select>`; optional           |
| `Empty`      | `<div>`                     | shown when nothing matches and nothing is loading                                |
| `Status`     | `<div role="status">`       | a live region for "Searching…" or a result count                                 |

**Items are data, not children.** Pass every option to the Root as `items`. The Root filters them, and `List`
renders what is left. An item can be a string, or an object with a `label`. Otherwise, give
`itemToString` for its label and `itemToKey` for its identity.

## Keyboard

Focus stays in the input. The highlighted option is announced through `aria-activedescendant`.

| Key                         | Does                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------- |
| typing                      | opens the list and filters it                                                            |
| ↓ ↑                         | opens the list at the selected or first item, then moves, wrapping                       |
| Alt+↓                       | opens the list without highlighting                                                      |
| Home, End                   | the first or last item, while open                                                       |
| Enter                       | picks the highlighted item                                                               |
| Esc                         | closes the list, putting the text back                                                   |
| Tab                         | closes the list, and focus moves on                                                      |
| Backspace in an empty input | with `multiple`, removes the last item                                                   |
| ← at the start of the text  | with `multiple`, moves into the chips: ← → between them, Backspace or Delete removes one |

## Single and multiple

<Example name="combobox-multiple" layout="stack">
  <ComboboxMultiple client:load />
</Example>

| Interaction             | Single                                            | `multiple`                                        |
| ----------------------- | ------------------------------------------------- | ------------------------------------------------- |
| Pick an item            | the input shows its label; the list closes        | added as a chip; the text clears; the list closes |
| Pick a selected item    | stays selected                                    | removed                                           |
| Empty the input         | the selection clears                              | the selection stays                               |
| Esc, or a press outside | closes; the input goes back to the selected label | closes; the text clears                           |
| Clear (×)               | clears the text and the selection                 | clears the text and every item                    |

**A selection survives a search that no longer returns it.** `value` holds the items
themselves, not their keys. So search "book" and pick, then search "pen" and pick: the books stay
selected, keep their chips and labels, and are still submitted with the form.

### Pre-selected items

Start with a selection through `defaultValue`, or `value` when controlled. A single combobox
shows the label in the input, and `multiple` shows a chip per item. Both examples above start
with one.

### Disabled items: can't be selected

<Example name="combobox-disabled" layout="stack">
  <ComboboxDisabled client:load />
</Example>

Mark an option `disabled` on its `Item`. It can't be picked, and the arrow keys skip it. It is
announced as unavailable through `aria-disabled`, and styled from `data-disabled`. This works
the same in single and multiple select, as `disabled` on a native `<option>` does: it stops a
pick only, and an item that is already selected can still be removed.

### Selections can always be removed

As with a native `<select multiple>`, every selected item can be removed, `disabled` or not.
There is no locked item. If your app needs one to stay, such as a code owner among reviewers,
control `value` and put it back in `onValueChange`:

```tsx
<Combobox.Root
  multiple
  value={reviewers}
  onValueChange={(next) => setReviewers([...owners, ...next.filter((r) => !owners.includes(r))])}
>
```

To fix a single selection, disable the whole field with `disabled` on the Root.

## Groups

<Example name="combobox-grouped" layout="stack">
  <ComboboxGrouped client:load />
</Example>

Group items as a native `<optgroup>` does. Pass groups as `items`: each an object with an
`items` array, plus whatever you render for it, such as a `label`. The List's function then gets
one group at a time. Render a `Group` with its `GroupLabel` and an `Item` per item:

```tsx
<Combobox.Root items={regions}>
  <Combobox.Input />
  <Combobox.Popup>
    <Combobox.Empty>No countries found.</Combobox.Empty>
    <Combobox.List>
      {(region: Region) => (
        <Combobox.Group key={region.label} disabled={region.comingSoon}>
          <Combobox.GroupLabel>{region.label}</Combobox.GroupLabel>
          {region.items.map((country) => (
            <Combobox.Item key={country} value={country}>
              {country}
            </Combobox.Item>
          ))}
        </Combobox.Group>
      )}
    </Combobox.List>
  </Combobox.Popup>
</Combobox.Root>
```

- **Search** runs inside each group, and a group with no match is left out. `region.items`
  already holds only the matches.
- **The arrow keys** move through every group as one list. They skip the labels and disabled
  items.
- **`disabled` on a Group** disables every item in it, as `<optgroup disabled>` does.
- **The value** is still an item, never a group. A group is any object with an `items` array,
  so an item type with its own `items` array can't be listed ungrouped.
- Groups don't nest, as with `<optgroup>`.
- **`Combobox.Separator`** draws a line between items or groups, as an `<hr>` in a `<select>`.
  It is visual only (`aria-hidden`), since a listbox may hold only options and groups. The
  example above puts one between each region.

## Creating an item

<Example name="combobox-creatable" layout="stack">
  <ComboboxCreatable client:load />
</Example>

Offer **Create "x"** when the text matches nothing, as GitHub's label picker does. It is a
pattern, not a prop. The "Create" row is an ordinary item that you add to `items`:

1. Track the text with `onInputValueChange`.
2. While no item matches it exactly, ignoring case and accents, add a "Create" item. Give it the
   text as its label, so a pick puts the new name in the input, and render it as "Create …" in
   its `Item`.
3. In `onValueChange`, swap the "Create" item for the real item you make, and add that to your
   list.

```tsx
const exact = labels.some((l) => fold(l.name) === fold(text));
const items = text && !exact ? [...labels, { id: `create:${text}`, name: text, create: true }] : labels;

<Combobox.Root
  items={items}
  multiple
  value={value}
  onValueChange={(next) => setValue(next.map((l) => (l.create ? createLabel(l.name) : l)))}
  onInputValueChange={setText}
>
```

The arrow keys and Enter reach the "Create" row like any other. Making the item is up to you:
saving it, asking your server for an id, or opening a [Dialog](/components/dialog/) for a
colour first.

## Search

By default, an item matches when its label contains the text, ignoring case and accents: "cote"
finds "Côte d’Ivoire". To search another way, pass `filter`. It receives the whole list, so it
can rank as well as narrow.

```ts
filter?: (items: T[], query: string, itemToString: (item: T) => string) => T[]
```

### Fuzzy search

<Example name="combobox-fuzzy">
  <ComboboxFuzzy client:load />
</Example>

A library like `match-sorter` or `Fuse.js` plugs in the same way. To narrow with the default
first, import it as `defaultFilter` from `@arun-dev/headless/combobox`.

### Server search

Set `filter={null}` to turn local filtering off. Fetch in `onInputValueChange`, pass the
results as `items`, and set `loading` while a request is in flight. Selected items do not have
to be in `items`.

<Example name="combobox-async" layout="stack">
  <ComboboxAsync client:load />
</Example>

`onInputValueChange` receives a reason as its second argument: `'input'` when someone typed,
`'item-press'`, `'clear'` or `'blur'` when the component reset the text. Use it to skip a
request you don't need.

## Lazy loading

Give the Root `onLoadMore`. It is called when the end of the list scrolls into view, and not
while `loading` is set. While loading, the list is `aria-busy` and `Empty` stays hidden.

## Virtualization

For thousands of items, render only the visible rows with a virtualizer such as
[TanStack Virtual](https://tanstack.com/virtual). The virtualizer needs to know how many rows
there are, so filter the items yourself, with `defaultFilter` or your own, and pass them with
`filter={null}`. `onItemHighlighted` tells it which row to scroll to. The highlighted option has
to be rendered for `aria-activedescendant` to reach it.

```tsx
import { useMemo, useRef, useState } from 'react';
import { useVirtualizer } from '@tanstack/react-virtual';
import { Combobox } from '@arun-dev/ui';
import { defaultFilter } from '@arun-dev/headless/combobox';

function BigCombobox({ all }: { all: string[] }) {
  const [query, setQuery] = useState('');
  const items = useMemo(() => defaultFilter(all, query, String), [all, query]);
  const scrollRef = useRef<HTMLElement>(null);
  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => scrollRef.current,
    estimateSize: () => 32,
  });

  return (
    <Combobox.Root
      items={items}
      filter={null}
      // Only typed text filters; a picked label or a reset shows everything.
      onInputValueChange={(text, { reason }) => setQuery(reason === 'input' ? text : '')}
      onItemHighlighted={(_, { index, reason }) => {
        if (reason === 'keyboard') virtualizer.scrollToIndex(index);
      }}
    >
      <Combobox.Input aria-label="Item" />
      <Combobox.Popup ref={scrollRef}>
        <Combobox.List style={{ blockSize: virtualizer.getTotalSize(), position: 'relative' }}>
          {virtualizer.getVirtualItems().map((row) => {
            const item = items[row.index];
            return (
              <Combobox.Item
                key={item}
                value={item}
                style={{ position: 'absolute', insetBlockStart: row.start, inlineSize: '100%' }}
              >
                {item}
              </Combobox.Item>
            );
          })}
        </Combobox.List>
      </Combobox.Popup>
    </Combobox.Root>
  );
}
```

### With groups

Flatten the groups into rows, labels and items, for the virtualizer, and wrap the rows in view
in their `Group`. Keep a group's label when it scrolls out, `hidden`, so the group stays named.
`onItemHighlighted` gives the index among items, so map it to its row.

```tsx
// Memoised: a new array each render is a new result list, which clears the highlight.
const groups = useMemo(() => filterGroups(regions, query), [query]);
const rows = useMemo(
  () => groups.flatMap((group) => [{ group }, ...group.items.map((item) => ({ group, item }))]),
  [groups],
);
const rowOfItem = rows.flatMap((row, i) => (row.item ? [i] : []));

<Combobox.Root
  items={groups}
  filter={null}
  onItemHighlighted={(_, { index, reason }) => {
    if (reason === 'keyboard') virtualizer.scrollToIndex(rowOfItem[index]);
  }}
>
  …
  <Combobox.List>
    {inViewByGroup(virtualizer.getVirtualItems(), rows).map(({ group, rows: inView }) => (
      <Combobox.Group key={group.label}>
        <Combobox.GroupLabel hidden={inView[0].item !== undefined}>{group.label}</Combobox.GroupLabel>
        {inView.map(({ item }) => item && <Combobox.Item key={item} value={item}>{item}</Combobox.Item>)}
      </Combobox.Group>
    ))}
  </Combobox.List>
```

A disabled item is skipped by the arrow keys only once it has rendered. That holds for every
virtualized list, grouped or not.

Below about a thousand items, you rarely need this. Filtering runs behind `useDeferredValue`, so
typing stays responsive, and moving the highlight re-renders only the two items it moves
between.

## Forms

Give the Root a `name`. It renders one hidden input per selected item, holding the item's key
(`itemToKey`), so the form submits `name=key` once per item. `form.reset()` returns the
selection and the text to what they were at mount.

Add `required` and the form won't submit until something is selected. The browser reports it
with its own message, the input matches `:invalid`, and `form.checkValidity()` returns
`false`. Text that was typed but never picked counts as nothing selected. With `multiple`, one
chip is enough.

```tsx
<Combobox.Root items={countries} name="country" required>
```

With react-hook-form, bind it through `Controller` and its `rules={{ required: true }}`, and pass
`aria-invalid` to `Combobox.Input`. The field's border turns red from it.

## Notes

- Keep `itemToString`, `itemToKey` and `filter` stable: define them outside the component, or
  wrap them in `useCallback`. A new function each render filters the list again on every
  render.
- Label the field with a `<label htmlFor>` pointing at the Input's `id`, or with `aria-label`.
- Not supported, by design: nested groups, an input inside the popup, action rows such as
  "Edit labels", an always-visible inline list, grid navigation, and a built-in virtualizer. Put
  an action beside the field, in a Menu or a link, and bring your own virtualizer.
- Restyle every combobox with the `--combobox-*` tokens, e.g. `--combobox-popup-max-height`.
- Types come from the package that owns them. `ComboboxInputProps` comes from
  `@arun-dev/ui`; the other parts' props come from `@arun-dev/headless/combobox`, or use
  `ComponentProps<typeof Combobox.Item>`.
