## When to use

- Tags on an item: "React", "TypeScript"
- Applied filters above a list
- Metadata in a compact row

Not for a status at a glance — use a Badge.

**Choosing between small labels:**

| Component                   | Use it for                                         | For example                          |
| --------------------------- | -------------------------------------------------- | ------------------------------------ |
| [Badge](/components/badge/) | The status or category of something, at a glance   | "Paid", "Overdue", "Beta"            |
| **Chip**                    | Tags, filters and metadata, often several in a row | "React", "Remote", an applied filter |
| [Kbd](/components/kbd/)     | A key on the keyboard, in text or a tooltip        | Press ⌘ K to search                  |

## Semantics matter more than styling

A chip is a shape, not an element. In a list it must be an `li`; when it is clickable it must
be a real `button`, or it is invisible to keyboards and screen readers. `render` supplies the
styling while you keep the right element.

## Notes

- `<Chip render={<button />}>` needs `type="button"` on the element, or it defaults to
  `type="submit"` and will submit an enclosing form.
- `Badge` builds on `Chip`'s shape — a badge carries both `chip` and `badge` classes.
