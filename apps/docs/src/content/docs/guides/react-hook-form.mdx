Every form control binds to react-hook-form one of two ways, and which one depends on where the
control keeps its value:

- **On a native element** — an `<input>`, `<textarea>` or `<select>` — bind it with `register()`,
  as you would the element itself.
- **In React** — a `<button role="checkbox">`, a list of options, a pair of thumbs — bind it with
  `Controller`. `register()` [fails quietly](#use-controller) on these.

| Control                                                        | Binding                                                             | Value                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| [Input](/components/input/), [Textarea](/components/textarea/) | `register()`                                                        | `string`                                                      |
| [Select](/components/select/)                                  | `register()`                                                        | `string`, `''` for the "Choose…" option                       |
| [Slider](/components/slider/)                                  | `register(name, { valueAsNumber: true })`                           | `number`                                                      |
| [DatePicker](/components/date-picker/)                         | `register()`                                                        | `'YYYY-MM-DD'`, or `'YYYY-MM-DDTHH:mm'` with `withTime`; `''` |
| [DateRangePicker](/components/date-picker/)                    | `register()` for each end, in `startInputProps` and `endInputProps` | two strings, as DatePicker's                                  |
| [Checkbox](/components/checkbox/)                              | `Controller`                                                        | `boolean`, or `'indeterminate'`                               |
| A group of Checkboxes                                          | `Controller`, one field                                             | `string[]`                                                    |
| [Switch](/components/switch/)                                  | `Controller`                                                        | `boolean`                                                     |
| [RadioGroup](/components/radio-group/)                         | `Controller`                                                        | `string \| null`                                              |
| [Combobox](/components/combobox/)                              | `Controller`                                                        | the item or `null`; an array with `multiple`                  |
| [RangeSlider](/components/range-slider/)                       | `Controller`, one field                                             | `[number, number]`                                            |
| [Calendar](/components/calendar/), RangeCalendar               | `Controller`                                                        | `'YYYY-MM-DD'`; `{ start, end }` for a range                  |
| [OTP input](/components/otp-input/#forms)                      | `Controller`                                                        | `string`                                                      |

## A whole form

Every control in one sign-up form: each wrapped in a [Field](/components/field/) for its label,
hint and error, bound with `register()` or `Controller` as the rest of this page explains, and
validated by react-hook-form.

<Example name="react-hook-form-signup" layout="stack">
  <ReactHookFormSignup client:load />
</Example>

Things to try:

- **Submit it empty.** Every rule fails at once, each message appears under its control, and
  focus moves to the first one.
- **Fix a field.** After a submit, each error updates as you type and disappears once the rule
  passes.
- **Pick the Free plan with more than 3 seats.** The seats rule reads another field, and `deps`
  re-checks it when the plan changes.
- **Enter a wrong code.** The form submits, the server check fails, and `setError` puts its
  message on the code and focuses it. 123456 is the right one.
- **Reset.** `reset()` returns every control to its default, the Controller-bound ones included.

Radio group and the interests are groups of controls, so they are a `<fieldset>` with a
`<legend>` rather than a Field, which names one control, styled with
[the fieldset classes](/components/field/#a-group-of-controls). Their error is tied to the group
with `aria-describedby`.

## A form to copy, for each kind of control

Each form below is complete: copy it, rename the fields, and keep the controls you need. Submit
one to see exactly what `handleSubmit` receives.

### Text, a list, a number and dates: register()

Input, Textarea, Select, Slider, DatePicker and DateRangePicker. `Field.Control` renders the
control and takes the spread, so the label, the description and the invalid state are tied to the
native element itself.

<Example name="react-hook-form-register" layout="stack">
  <ReactHookFormRegister client:load />
</Example>

- A Slider's value is a string on the element; `valueAsNumber` makes it a number in the form.
- A DateRangePicker is two native inputs, so it is two fields, `from` and `to`. A rule on one can
  read the other through its second argument.

### Yes or no, one of a few, several of a few: Controller

Checkbox, a group of Checkboxes, Switch and RadioGroup. Pass `field.value` and `field.onChange`
under the control's own names — `checked` and `onCheckedChange`, `value` and `onValueChange` — and
`field.onBlur`.

<Example name="react-hook-form-choices" layout="stack">
  <ReactHookFormChoices client:load />
</Example>

- A group of Checkboxes is one array field: each box adds or removes its own value.
- "Accept the terms" uses `validate`, not `required`, and stores `checked === true`, so the
  field is a plain `boolean` (see [Checkbox's third state](#checkboxs-third-state)).

### Search, a range, a calendar and a code: Controller

Combobox, alone and with `multiple`, RangeSlider, Calendar and OtpInput.

  <ReactHookFormPickers client:load />
</Example>

- Combobox's `Combobox.Input` is the Field's control, so pass it `field.ref` and `field.onBlur`;
  the value goes on `Combobox.Root`.
- RangeSlider's value is the pair, one field, and a rule reads both ends.
- RangeSlider and Calendar are groups of controls rather than one, so their label and error are
  tied to them by id, with Field's classes (`.field`, `.field-label`, `.field-error`) for the look.

## Use Controller

```tsx
import { Controller, useForm } from 'react-hook-form';
import { Checkbox } from '@arun-dev/ui';

const { control, handleSubmit } = useForm({ defaultValues: { terms: false } });

<Controller
  control={control}
  name="terms"
  render={({ field }) => (
    <Checkbox.Root
      checked={field.value}
      onCheckedChange={field.onChange}
      onBlur={field.onBlur}
      aria-label="Accept terms"
    >
      <Checkbox.Indicator />
    </Checkbox.Root>
  )}
/>;
```

`Switch` is the same, with `Switch.Root` and `Switch.Thumb`. `useController` works equally well
if you prefer a hook to a render prop.

<Aside type="danger" title="register() fails silently">
Spreading `register('terms')` onto `Checkbox.Root` or `Switch.Root` type-checks, renders, and
looks right on screen. The control flips when clicked — and the form keeps its default value.
No error, no warning. `useWatch` reports the stale value forever, and the form submits something
the user never chose.

`register()` returns props for a native input:

| prop       | goes to          | result                                            |
| ---------- | ---------------- | ------------------------------------------------- |
| `ref`      | the `<button>`   | it has no `.checked`, so there is nothing to read |
| `onChange` | the `<button>`   | a `<button>` never fires a `change` event         |
| `name`     | the hidden input | works, and is the only part that does             |

The control's state lives in React, not on an element react-hook-form can inspect. That is the
cost of the element choice described in [Components](/headless/components/), and `Controller`
is what it is for.

</Aside>

### Radio group: native, and still Controller

A radio group's items are real `<input type="radio">` elements, so `register()` gets further
there. It reads them correctly: a click reaches the form, and the form submits it. It still cannot
_write_ to them. `setValue` and `reset` set `.checked` on the DOM directly, and the group's value
never hears of it. The radio shows checked while its `data-checked` stays on the old one, and a
later render puts the old one back.

That is a property of the value living in React rather than of the element, so it would not
change with a different element either. Bind the group with `Controller`, passing `field.value`
to `value` and `field.onChange` to `onValueChange`:

```tsx
<Controller
  control={control}
  name="plan"
  render={({ field }) => (
    <RadioGroup.Root
      name={field.name}
      value={field.value}
      onValueChange={field.onChange}
      onBlur={field.onBlur}
      aria-label="Plan"
    >
      <label>
        <RadioGroup.Item value="free" />
        Free
      </label>
    </RadioGroup.Root>
  )}
/>
```

## What works once it is bound

All of this is covered by a contract spec in `@arun-dev/ui`, so it stays true:

|                                              | Checkbox | Radio group   | Switch |
| -------------------------------------------- | -------- | ------------- | ------ |
| `Controller` / `useController`               | ✅       | ✅            | ✅     |
| `useWatch` and `watch`                       | ✅       | ✅            | ✅     |
| `setValue` drives the control                | ✅       | ✅            | ✅     |
| `reset()` drives the control                 | ✅       | ✅            | ✅     |
| Native `form.reset()` keeps the form in step | ✅       | ✅            | ✅     |
| `rules` validation, errors block submit      | ✅       | ✅            | ✅     |
| `formState.isDirty`                          | ✅       | ✅            | ✅     |
| `disabled` cannot move the value             | ✅       | ✅            | ✅     |
| `register()`                                 | ❌       | ❌ reads only | ❌     |

The native reset row is worth a moment. A `<button type="reset">` resets the hidden input by
itself, and the control returns to the state it mounted with — but react-hook-form only hears
about that because the change is reported through `onCheckedChange` (`onValueChange` for a radio
group), the same callback a click goes through. Without that it would show one value and hold another.

## Three things to watch

**`name` is redundant under Controller, and not harmless.** `name` makes the control render a
hidden input for native form submission. Under `Controller`, react-hook-form owns the value, and
the hidden input will _also_ appear in a native `FormData` read of the form. Pass `name` for
native submission, or use `Controller`, not both. A radio group is the exception: it always has a
name, generated if you omit it, so pass `field.name` and a native read at least sees the field's
own.

**Do not rely on `field.ref`.** It resolves to the `<button>`, not the hidden input, so
react-hook-form's focus-on-error lands on the right element but any value read through it is
`undefined`. Passing it is harmless; trusting it is not.

**`required` treats `false` as missing.** `rules={{ required: 'Required' }}` on an unchecked
control blocks submit, which is what you want for "accept the terms" and wrong for a genuine
yes/no. Use `validate` when `false` is a legitimate answer.

## Checkbox's third state

`checked` is `boolean | 'indeterminate'`, and that value round-trips through react-hook-form
unchanged — `useWatch` reports `'indeterminate'`, and `handleSubmit` hands you the literal
string. Correct, and almost never what an API wants. Resolve it at the edge:

```tsx
handleSubmit((data) => save({ terms: data.terms === true }));
```

## Input, Textarea and Select: use register()

`Input` keeps nothing in React. The value lives on the `<input>`, which is exactly what
`register()` reads and writes, so spread it straight on:

```tsx
const { register, formState } = useForm({ defaultValues: { email: '' } });

<label htmlFor="email">Email</label>
<Input
  id="email"
  type="email"
  aria-invalid={formState.errors.email ? true : undefined}
  {...register('email', { required: true })}
/>
```

`ref`, `name`, `onChange` and `onBlur` all land on the `<input>`, never on the box, whether or not
the input has slots. `setValue`, `reset()`, validation and `isDirty` work with no extra wiring.
Set `aria-invalid` from `formState.errors` to turn the border to the error colour.

`Textarea` binds the same way, with the same spread. It has no box, so everything lands on the
`<textarea>` directly.

`Select` binds the same way too; like Input, `ref`, `name` and the handlers land on the
`<select>`, not its box. For a "Choose…" prompt, add an `<option value="">` and a `required`
rule: react-hook-form treats the empty string as missing.

`Slider`, `DatePicker` and `DateRangePicker` bind the same way, since each is native inputs too:
a Slider with `valueAsNumber`, a DateRangePicker with one `register()` in each of
`startInputProps` and `endInputProps`. The [first form to copy](#text-a-list-a-number-and-dates-register)
has all of them.

`Controller` works too, if a field needs a transformed value, but it isn't required.

## Buttons

`Button` defaults to `type="button"`, so a button inside a form does nothing until told
otherwise. Give the submit button `type="submit"` for `handleSubmit` to run.

While an async `onSubmit` runs, pass `formState.isSubmitting` to `pending`: the button is disabled,
so a second press or Enter in a field cannot submit again, and a Spinner shows over its label.

```tsx
<Button type="submit" variant="primary" pending={formState.isSubmitting}>
  Save
</Button>
```

For a reset, call react-hook-form's `reset()` from a `type="button"`, as the forms above do, so the
form state and every control return together. An error only the server can find goes back on its
field with `setError(name, { message }, { shouldFocus: true })`, as the whole form does for the
code.
